# WebRTCとは何か、なぜ使うのか、どのように動作するか

この文書は、WebRTCの基本概念、メリット、動作原理についてまとめたものです。

---

## 1. WebRTCとは

### 定義

- **Web Real-Time Communication**の略
- APIでありプロトコルでもある
- 2つのWebRTCエージェント間で双方向の安全なリアルタイム通信を行うためのルール

### HTTPとの類似性

| WebRTC | HTTP/Web |
|--------|----------|
| WebRTCプロトコル | HTTP |
| WebRTC API | fetch API |

### 標準化

- **プロトコル**: IETFの[rtcweb](https://datatracker.ietf.org/wg/rtcweb/documents/)ワーキンググループで管理
- **API**: W3Cの[webrtc](https://www.w3.org/TR/webrtc/)で文書化

---

## 2. WebRTCを学ぶメリット

| メリット | 説明 |
|----------|------|
| オープンスタンダード | 標準化された技術 |
| 複数の実装 | JavaScript以外の言語でも利用可能 |
| ブラウザで利用可能 | 追加プラグイン不要 |
| 必須の暗号化 | セキュリティがプロトコルレベルで組み込み |
| NATトラバーサル | ファイアウォール越えが可能 |
| 輻輳制御 | ネットワーク状態に応じた制御 |
| 1秒未満のレイテンシー | リアルタイム通信が可能 |

## 3. WebRTCの4つのステップ

各ステップは順番に行われ、前のステップが100%成功しなければ次に進めません。

### ステップ1: シグナリング

2つのWebRTCエージェントが通信を開始するための情報交換。

**使用プロトコル**: SDP（Session Description Protocol）

**交換される情報**:
- エージェントが到達可能なIPおよびポート（候補）
- 送信するオーディオ/ビデオトラックの数
- サポートするオーディオ/ビデオコーデック
- 接続時に使用される値（uFrag/uPwd）
- セキュリティ確保時に使用される値（証明書のフィンガープリント）

**注意**: シグナリングはWebRTC自体では行わない。REST、WebSocket、認証プロキシなど既存のインフラを使用。

---

### ステップ2: 接続（STUN/TURNによるNATトラバーサル）

**使用プロトコル**: ICE（Interactive Connectivity Establishment）

| 技術 | 役割 |
|------|------|
| ICE | 2つのエージェント間の接続確立 |
| NATトラバーサル | 異なるサブネット間の通信を可能に |
| STUN | 自分のグローバルIPを発見 |
| TURN | 直接接続できない場合の中継サーバー |

---

### ステップ3: セキュリティ確保（DTLS/SRTP）

| プロトコル | 役割 |
|------------|------|
| DTLS | UDP上のTLS。DataChannelの暗号化に使用 |
| SRTP | RTPパケットの暗号化。音声/ビデオ通信に使用 |

**特徴**: 中央の認証局を使わず、シグナリングで共有したフィンガープリントと証明書を照合。

---

### ステップ4: 通信（RTP/SCTP）

| プロトコル | 用途 |
|------------|------|
| RTP | リアルタイムメディア（音声/ビデオ）伝送 |
| SCTP | DataChannelメッセージ送受信 |

**RTPの特徴**:
- 最小限の機能
- 開発者がレイテンシー、ロス、輻輳を制御可能

**SCTPの特徴**:
- 信頼性のない/順番のない配信オプション
- リアルタイムシステムに必要な低レイテンシー

## 4. WebRTCプロトコルスタック

WebRTCは既存の成熟した技術の組み合わせ：

```
┌─────────────────────────────────────┐
│           WebRTC Agent              │
├─────────────────────────────────────┤
│  シグナリング: SDP                   │
├─────────────────────────────────────┤
│  接続: ICE / STUN / TURN            │
├─────────────────────────────────────┤
│  セキュリティ: DTLS / SRTP          │
├─────────────────────────────────────┤
│  通信: RTP / SCTP                   │
└─────────────────────────────────────┘
```

## 5. JavaScript API

### 主要なAPI

| API | 役割 |
|-----|------|
| `new RTCPeerConnection` | WebRTCセッションのトップレベル。すべてのプロトコルを含む |
| `addTrack` | 新しいRTPストリームを作成。ランダムなSSRCを生成 |
| `createDataChannel` | SCTPストリームを作成（SCTPアソシエーションがない場合） |
| `createOffer` | リモートピアと共有するローカル状態のSession Descriptionを生成 |
| `setLocalDescription` | `addTrack`や`createDataChannel`の変更をコミット |
| `setRemoteDescription` | リモートピアの状態をローカルに設定（シグナリング） |
| `addIceCandidate` | リモートのICE候補を追加 |

### コールバック

| コールバック | タイミング |
|--------------|------------|
| `ontrack` | リモートピアからRTPパケットを受信したとき |
| `oniceconnectionstatechange` | ICEエージェントの状態が変化したとき（接続/切断） |
| `onconnectionstatechange` | ICEとDTLS両方の状態を反映（両方が正常完了で通知） |

## 6. まとめ

- WebRTCは2000年代初頭から存在するよく理解された技術の集合体
- 各部分を個別に学習できる
- 「WebRTCエージェント」は多くの異なるプロトコルを組み合わせたもの
