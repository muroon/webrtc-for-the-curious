# WebRTCの歴史

この文書は、WebRTCを構成するプロトコルの開発者へのインタビューを通じて、その歴史をまとめたものです。

---

## 1. RTPの歴史

### Ron Frederick氏について

- RTPおよびRTCPの共同著者
- 1996年1月にRFC 1889で定義
- Network Video tool（nv）の開発者

### nvの開発（1992年）

| 年月 | 出来事 |
|------|--------|
| 1992年10月 | IPマルチキャストベースのビデオ会議ツール開発開始 |
| 1992年11月 | nvをインターネットコミュニティに公開 |
| 1993年2月 | ソースコード公開 |
| 1993年3月 | ウェーブレットベースの圧縮方式導入 |
| 1993年5月 | カラービデオ対応 |
| 1994年7月 | 最終公開版 3.3beta リリース |

### 技術的な特徴

- **目標帯域**: 128kbps（家庭用ISDN回線相当）
- **圧縮率**: 約20倍
- **特許**: US5485212A（電話会議のためのソフトウェアビデオ圧縮）

### nvのユニークさ

| 従来のシステム | nv |
|----------------|-----|
| 圧縮に専用ハードウェアが必要 | 圧縮・解凍両方をソフトウェアで実行 |
| 高価 | アナログビデオをデジタル化するハードウェアのみ必要 |

### 圧縮技術の工夫

- コサイン変換や浮動小数点を避ける
- 整数の乗算も避ける（SPARCステーションでは遅いため）
- 加減算、ビットマスク、シフトのみで実装
- MPEG-1の基本概念をより安価なアルゴリズムで近似

## 2. RTP誕生の経緯

### 主要メンバー

| 名前 | 役割・所属 |
|------|-----------|
| Steve Deering | IPマルチキャスト開発者 |
| Van Jacobson | IPマルチキャスト開発者、RTP RFC著者 |
| Steve Casner | RTP RFC著者 |
| Henning Schulzrinne | RTP RFC著者 |
| Ron Frederick | RTP RFC著者、nv開発者 |

### MBONE（インターネット・マルチキャスト・バックボーン）

- IPマルチキャストの初期実験ネットワーク
- 各種オンラインコラボレーションツールの共通ベースプロトコルとしてRTPが誕生

### Ron氏の振り返り

**後悔・不満点**:
- RTCPの実装が複雑すぎた
- これがRTPの広範な採用を妨げた
- ユニキャストではRTCPの機能の多くが不要

**もっとやればよかったこと**:
- IPマルチキャストの採用を研究機関以外にも推進すべきだった
- ケーブル/放送テレビからインターネットベースへの移行が早まったはず

## 3. WebRTCの歴史

### Serge Lachapelle氏について

- Googleのプロダクトマネージャー（現在はGoogle Workspace担当）
- Marratech社の共同設立者（2007年にGoogleが買収）
- 90年代からコミュニケーションソフトウェアに情熱

### Marratechでの経験

```
マルチキャスト時代
├── ネットワークに依存してパケット配信
├── サーバーがシンプル
└── 欠点: ネットワーク設計が必要

↓ 業界の移行

SFU時代（パケットシャッフル）
└── より柔軟なネットワーク対応
```

## 4. Googleでの取り組み

### 最初のプロジェクト: Gmailの音声・ビデオチャット

| コンポーネント | ライセンス元 |
|----------------|--------------|
| 音声 | GIPs |
| ビデオ | Vidyo |
| ネットワーク | libjingle |

- **Justin Uberti**がこれらのコンポーネントを統合
- NPAPIを使用（後にセキュリティ問題として認識）

### Chromeプロジェクト

- NPAPIからの脱却が焦点
- サンドボックス方式でユーザーの安全を確保
- 安全でない操作は別プロセスで実行

## 5. WebRTC誕生の動機

### 3つの動機

| 動機 | 説明 |
|------|------|
| 開発の簡素化 | 同じものを異なる開発者が再実装する無駄をなくす |
| オープン性 | テキストやHTMLと同様に、音声・映像もオープンであるべき |
| セキュリティ | NPAPIの問題を解決し、デフォルトで安全なプロトコルを作る |

### 買収によるオープンソース化

| 企業 | 技術 |
|------|------|
| On2 Technologies | ビデオ技術（VP8等） |
| Global IP Solutions (GIPs) | RTC技術 |

## 6. 標準化プロセス

### 主要人物

- **Harald Alvestrand**: IETFでの標準化プロセスを開始

### 2010年マーストリヒト会議

非公式の昼食会で、WebRTCのあるべき姿を議論。

**参加企業**:
- Google
- Cisco
- Ericsson
- Skype
- Mozilla
- Linden Labs

### 標準化の方針

| 方針 | 理由 |
|------|------|
| 既存技術の活用 | IETFの作業は既存の作業の延長線上にある |
| シグナリングの再標準化は行わない | SIP等で既に解決済み、政治的問題になりかねない |

### 2つの標準化団体

| 団体 | 担当 |
|------|------|
| IETF | プロトコル（rtcwebワーキンググループ） |
| W3C | API |

## 8. まとめ

### WebRTCの成功要因

1. **既存技術の活用**: RTP等の成熟した技術の上に構築
2. **オープンソース化**: 買収した技術をオープンソースとして公開
3. **標準化**: IETFとW3Cの協力、多くの企業の参加
4. **セキュリティ**: デフォルトで暗号化

### 歴史的な流れ

```
1992年: nv開発（Ron Frederick）
    ↓
1996年: RTP標準化（RFC 1889）
    ↓
2007年: Marratech買収（Google）
    ↓
2010年: WebRTC標準化開始（マーストリヒト会議）
    ↓
2011年: On2、GIPs買収・オープンソース化
    ↓
現在: クラウドとの融合、新しい用途への拡大
```
